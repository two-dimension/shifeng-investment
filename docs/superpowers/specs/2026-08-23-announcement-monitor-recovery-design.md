# 公告监控恢复设计

## 背景与根因

现有“公告监控”页面和 `/api/research` 路由仍然存在，但 `cninfo` 数据只会从旧机器上的 `/Users/rayw/Documents/巨潮资讯/output` 导入。当前机器没有该目录，也没有 `server/data/research` 历史缓存。因此手动刷新会得到 `attempted: 0`，页面没有可展示日期，同时用户仍会看到“同步完成”的误导提示。

恢复方案不再依赖旧自动化目录。服务端直接读取巨潮资讯公开公告接口，生成现有 `ResearchSummary` 契约并写入本地缓存。旧目录导入能力继续保留，只作为兼容路径。

## 第一阶段目标

- 恢复 `cninfo`“公告研判”页签；业绩预告、业绩报告和风险提示继续沿用已有导入逻辑，不在本阶段重建。
- 每日抓取沪深市场公告总量，并对平台当前组合中的 A 股持仓做重点匹配与研判。
- 支持页面手动刷新最近交易日、服务端每日自动刷新、历史日期浏览和原公告跳转。
- 官方源临时失败时保留上一版缓存，不覆盖已有可用数据，并向页面返回明确错误。
- `attempted: 0` 不再被描述为成功更新。

## 非目标

- 第一阶段不下载或解析全部公告 PDF。
- 第一阶段不使用大模型生成公告正文摘要。
- 第一阶段不恢复旧机器上的 Excel/PDF 报告生产程序。
- 第一阶段不把港股、美股或基金代码送入巨潮查询。
- 第一阶段不重做现有公告监控页面布局。

## 方案选择

采用“巨潮直采 + 确定性标题规则 + 原子缓存”。相比只修正硬编码目录，它不依赖已经丢失的本地产物；相比引入第三方付费源，它没有新增密钥、费用或供应商锁定。标题规则的能力低于正文研判，但足以先恢复稳定、可解释的监控，后续可对命中持仓的少量 PDF 增加深度摘要。

## 架构

新增一个独立的巨潮公告源模块，负责分页请求、响应校验、去重和 URL 标准化。它不直接操作 Express，也不写文件，便于用注入的 `fetch` 做单元测试。

新增一个公告研判模块，负责：

1. 从 `server/data/funds.json` 汇总组合名称和六位 A 股代码；
2. 将官方公告与组合持仓匹配；
3. 根据公告标题中的确定性关键词生成正向、负向或中性分数；
4. 聚合同公司多条公告，生成现有页面可消费的 `topGood`、`topBad`、`allGood` 和 `allBad`；
5. 保留原公告 PDF 链接、公告时间、命中组合标签和规则命中依据。

`researchSync` 保留旧产物优先策略：指定日期存在旧 `processed_*.json` 和报告文件时沿用原有导入；否则对 `cninfo` 启用官方直采回退。直采结果写入 `server/data/research/cninfo/YYYY-MM-DD.json`，不要求同时生成 Excel/PDF 文件。

## 数据流

页面点击“刷新”后调用现有 `POST /api/research/sync`。当 `kind=cninfo` 且未指定日期时，服务端选择上海时区最近若干个工作日，从最近日期向前尝试，直到得到一个有公告的可用日期；指定日期时只请求该日。

每个日期分别请求沪市和深市，按接口分页上限逐页获取。服务端保存全市场 `totalCount`，但只为当前组合中匹配到的 A 股构造详细条目。相同 `announcementId` 只保留一次。成功结果经临时文件写入后原子替换正式 JSON，避免进程中断留下半文件。

现有 `latest/history/:date` API 和前端数据类型保持不变。直采快照的 `files` 为空，页面仍通过条目中的官方 PDF URL 打开原公告。

## 研判规则

规则只基于公告标题并保持可解释性。每条规则包含关键词、方向、权重和简短说明；多个规则命中时累加并限制在 `-10..10`。

正向示例包括增持、回购、中标、签订重大合同、业绩预增、扭亏、分红和获得批复。负向示例包括减持、立案、处罚、退市风险、诉讼、冻结、质押风险、业绩预减、首亏和重大亏损。仅含“提示性公告”“进展公告”等无方向词的标题保持中性，不进入利好/利空榜。

条目摘要明确写出命中的标题规则，不把标题分类描述成已经阅读正文后的事实判断。多公告公司按绝对值最高的公告作为主标题，并记录当日公告数。

## 调度与历史

沿用现有每日 `22:10` 的研究同步任务。同步 `all` 时：

- `cninfo` 即使旧目录不存在，也会执行官方直采；
- 其余三个品类在源目录缺失时继续跳过，不阻塞 `cninfo`；
- 只有确实抓取、导入或验证到缓存可用时，才计入成功完成。

手动刷新默认只恢复最近一个有数据的交易日，避免一次点击触发 14 天全量网络抓取。历史回填通过显式日期调用完成，后续可再增加后台批量回填任务。

## 错误处理与可观测性

- 官方请求设置超时，并对 `429`、`5xx` 和网络错误做有限次数退避重试。
- 任一市场分页失败时，该日期同步失败，不写入不完整快照。
- 响应不是 JSON、缺少公告数组或分页计数异常时视为上游契约错误。
- 同步响应增加可读的 `source`、`attempted`、`fetched`、`matched` 和错误信息，保留现有汇总字段兼容前端。
- 页面在 `attempted: 0` 时显示“未找到可同步来源”，在上游失败时显示具体错误；已有历史数据仍可浏览。

## 测试策略

- 公告源单元测试覆盖分页、沪深合并、去重、超时/错误和不完整分页拒绝。
- 研判单元测试覆盖 A 股代码筛选、组合标签聚合、正负/中性规则、多公告聚合和分数边界。
- `researchSync` 集成测试覆盖旧产物优先、旧目录缺失时官方回退、失败不覆盖缓存、手动最近交易日恢复。
- API 测试覆盖真实同步结果映射和 `attempted: 0` 的错误语义。
- 最终运行服务端测试、前端类型检查与生产构建，并用官方接口完成一次受控日期同步验证。

## 后续增强

第一阶段稳定后，只对持仓命中的高优先级公告下载 PDF，提取正文事实并生成引用式摘要；标题规则仍作为无模型时的可靠降级。若未来需要北交所覆盖，再依据官方接口参数和组合持仓需求独立增加，不与本次沪深恢复捆绑。
